# Project Planning and Scope

## Objective

To choose a suitable personal utility application for MP1 and define a manageable scope that satisfies the project requirements.

## AI Assistance

I asked the AI to compare two possible project ideas: a personal warranty and expiry tracker, and a job application tracker. The AI compared their feasibility, possible extensions, and similarity to the prohibited to-do manager domain. It recommended the job application tracker because it had a clear workflow and opportunities for additional design complexity.

## My Decisions

I selected the job application tracker and named it ApplyTrack. I decided that it would track only applications that had already been submitted, rather than potential jobs of interest. I also chose to begin with a focused MVP and postpone features such as statistics, status history, importing and exporting until the core features are reliable.

## Verification

I checked the official MP1 project description and verified that ApplyTrack must be implemented as a Java desktop application and that its job-application workflow is different from the prohibited to-do manager functionality. I also reviewed the proposed MVP to ensure that it was substantial but could be implemented incrementally.

## Outcome

The selected product was ApplyTrack, a Java desktop application for managing submitted job applications. Its target user, problem statement, initial data fields, allowed statuses, MVP features and deliberate exclusions were defined. The implementation will proceed one small feature at a time.
